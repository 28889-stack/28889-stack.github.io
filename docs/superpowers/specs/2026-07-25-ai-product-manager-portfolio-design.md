# AI 产品经理个人主页设计规格

日期：2026-07-25

## 1. 项目目标

为董羽舒制作一套中文求职个人主页，静态部署至 GitHub Pages。

主页首先证明 AI 产品实习能力，其次展示两个独立项目，再以法律与金融复合知识说明其在垂类 Agent 产品上的差异化优势。页面不复刻传统简历，也不使用虚构项目、虚构指标或没有真实内容支撑的栏目。

## 2. 目标受众与成功标准

### 目标受众

- AI 产品经理岗位的招聘负责人
- AI 产品团队负责人
- 关注 Agent、RAG、模型评测和垂类应用的业务负责人

### 成功标准

- 用户进入首屏后能立即识别“AI 产品经理”定位。
- 实习经历是页面最主要的内容。
- 三段实习默认保持简洁，点击后可查看具体产品工作和结果。
- 两个项目能体现从问题定义到方案落地的独立能力。
- 法律与金融背景被表达为垂类 Agent 产品优势，而不是独立求职方向。
- 页面在桌面端和移动端均可顺畅阅读和操作。
- GitHub Pages 可直接部署，无服务端依赖。

## 3. 信息架构

页面采用单页滚动结构，不设置 Tab 页面。

内容顺序：

1. Header
2. Hero
3. 实习经历
4. 代表项目
5. 核心能力
6. 法律 × 金融复合背景

Header 使用锚点导航：

- 关于我
- 实习经历

Header 右侧提供“发送邮件”按钮，不展示 GitHub、Twitter、LinkedIn、手机号或微信。

## 5. 视觉方向

视觉锚点为暗黑系现代 SaaS，但保持克制。

### 色彩

- 页面背景：`#0D0E11`
- 卡片背景：`#121316`
- 浮层背景：带透明度的深灰
- 主文字：纯白或接近纯白
- 次要文字：中性灰
- 主要点缀色：低饱和极光蓝
- 次要点缀：仅用于微弱渐变的紫色
- 霓虹绿仅用于极少量状态或 Hover，不作为大面积品牌色

### 字体

- 主字体：Geist，失败时回退到 Inter、SF Pro Display 和系统无衬线字体。
- 标题使用较紧字距和高字重。
- 正文保持充足行高，中文不使用过度压缩字距。

### 材质

- 背景包含低对比度网格或点阵纹理。
- 卡片使用 1px 半透明边框。
- 玻璃拟态只用于 Header、展开详情层和少量重点卡片。
- 阴影保持柔和，不使用高亮外发光。
- Hover 仅包含轻微位移、边框变亮和背景透明度变化。

### 图标

- 使用 Lucide React 图标组件。
- 图标保持统一线宽和尺寸。
- 不使用 Emoji、Unicode 字符或自制字符作为图标替代。

## 6. 响应式行为

### 桌面端

- 内容最大宽度约 1180 至 1280 px，所有主模块共用同一对齐网格。
- 实习卡片三列排列。
- 项目卡片两列排列。
- 能力卡片四列排列。
- 展开的实习或项目卡片跨越当前网格完整宽度。

### 平板端

- 实习卡片改为两列或一列。
- 能力卡片改为两列。
- Header 保留核心导航，缩减间距。

### 移动端

- 所有卡片单列。
- Header 导航折叠为菜单按钮。
- Hero 动态头像下移或降低尺寸。
- 展开详情采用自然文档流，不使用固定高度。
- 所有点击目标不小于 44 px。

## 7. 交互与可访问性

- 卡片使用可聚焦按钮或语义化触发器。
- 支持 Enter 和 Space 展开详情。
- 展开触发器提供 `aria-expanded` 与 `aria-controls`。
- 动画遵循 `prefers-reduced-motion`，关闭非必要运动。
- 文本与背景满足 WCAG AA 对比度。
- 锚点导航考虑固定 Header 的滚动偏移。
- 邮箱使用 `mailto:` 链接。

## 8. 技术方案

- 使用 Vite + React + TypeScript。
- 使用 CSS Modules 或单独的全局样式文件，不引入重量级 UI 框架。
- 使用 Lucide React 图标。
- 内容保存在集中式 TypeScript 数据文件中，组件只负责展示和交互。
- 构建输出为静态 `dist/`，适配 GitHub Pages 子路径部署。
- 使用 GitHub Actions 执行构建并部署 Pages。

建议组件边界：

- `Header`
- `Hero`
- `ExperienceSection`
- `ExpandableExperienceCard`
- `ProjectsSection`
- `ExpandableProjectCard`
- `SkillsSection`
- `CompoundBackground`
- `ContactFooter`

## 9. 验证范围

自动化验证：

- 内容数据包含三段实习、两个项目、四项核心能力。
- 页面不渲染 GitHub、Twitter、LinkedIn、手机号或微信链接。
- 卡片一次只展开一项。
- 展开按钮正确更新无障碍属性。
- 邮件按钮使用正确的 `mailto:` 地址。
- 生产构建在 GitHub Pages 基础路径下成功。

人工验证：

- 桌面端检查所有模块左右边界是否对齐。
- 移动端检查导航、卡片和展开详情是否溢出。
- 检查暗色背景下文本、边框和按钮对比度。
- 检查动态头像、Hover 和展开动画是否克制。
- 开启减少动态效果设置后确认非必要动画停止。

## 10. 明确不包含的内容

- 不展示个人证件照。
- 不展示 GitHub 或其他社交媒体链接。
- 不展示手机号或微信。
- 不设置 Insights / Writing 栏目。
- 不使用“3 段实习”“2 个项目”等统计式首屏内容。
- 不使用虚构技术栈、虚构文章、虚构数据或虚构结果。
- 不使用多页面 Tab 导航。
