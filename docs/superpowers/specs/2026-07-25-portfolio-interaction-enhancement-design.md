# AI 产品经理个人主页交互增强规格

日期：2026-07-25

## 1. 目标与边界

本次改版在现有浅色双栏主页上增加有记忆点、但服务于求职信息的交互。首屏负责建立“AI 产品经理”的识别度，正文负责证明腾讯、同花顺与易方达的实习经历。

本次不改变已确认的信息顺序、中文内容、暖白与陶土色视觉系统，也不增加新栏目。实习继续是页面主角；项目默认收起，减少纵向占用。

成功标准：

- 首屏 3 秒内出现一个清晰、可操作的 AI 产品闭环。
- 操作首屏节点后，能自然定位到对应的实习证据。
- 实习区域比项目区域更醒目，且详情仍可点击展开。
- 两个项目默认状态合计不超过当前项目区域高度的一半。
- 动效不造成滚动劫持、持续闪烁、内容位移或阅读干扰。
- 桌面端、触屏设备、键盘操作和减少动态效果模式均可使用。

## 2. 最终采用的交互组合

### 2.1 Hero AI 产品闭环

现有 `USER / MODEL / EVAL` 图形升级为一个语义化交互组件。

三个节点分别对应：

- `USER`：腾讯的用户反馈分类、周期报告与问题闭环。
- `MODEL`：同花顺的 Agent、RAG 与意图路由工作流。
- `EVAL`：Benchmark、自动化评测与 Badcase 归因。

默认状态突出中央 `AI PRODUCT`，外围节点保持低对比度。用户悬停、聚焦或点击节点时：

1. 当前节点变为陶土色实心状态；
2. 中央与节点之间的细线完成一次短距离描边；
3. 图形下方切换为一行对应经历证据；
4. 对应实习行执行一次短暂高亮。

鼠标移开后保留最后一次主动点击的节点；纯悬停只作为临时预览。移动端不依赖悬停，节点作为至少 44px 的按钮使用。

### 2.2 实习证据联动轨

腾讯、同花顺、易方达三行左侧增加一条连续的细轨道。轨道本身只表达阅读关系，不增加技术流程文案。

- Hero 节点变化时，对应实习行的轨道节点、公司名和相关标签同步高亮。
- 用户点击实习行后，详情按现有单开模式展开。
- 展开时轨道节点只执行一次由空心到实心的过渡。
- 展开内容不自动滚动，不改变其他摘要行的宽度。
- 如果目标实习区域尚未进入视口，只记录高亮状态，不强制跳转。

实习高亮是全页最明显的正文动效；项目、复合背景和能力卡片不使用同等级效果。

### 2.3 编辑式章节进度

现有 `01–04` 分区编号作为章节进度的视觉基础。

- 当前进入视口的章节编号与左侧细线切换为陶土色。
- 每个章节内容首次进入视口时执行一次 `opacity 0 → 1` 与不超过 8px 的位移。
- 不增加悬浮导航、Tab 或滚动劫持。
- 移动端只保留当前章节颜色反馈，不显示额外固定控件。

## 3. 项目折叠卡片

项目区域继续使用两列，但默认卡片显著压缩。

### 默认状态

每张卡片只显示：

- 项目编号与图标；
- 项目名称；
- 一句话定位；
- 最多 3 个标签；
- 一条由 3 个节点组成的结构预览；
- “展开项目”图标按钮。

默认不显示模拟运行的输入、路由、输出，也不显示完整 6 节点结构。

### 展开状态

点击卡片的完整摘要触发区域后显示：

- 暖色模拟运行面板：`INPUT / ROUTE / OUTPUT`；
- 完整项目结构；
- 收起按钮。

一次只展开一个项目。桌面端的两张摘要卡片始终保持并列、宽度和位置不变，展开内容以共用的完整宽度详情面板出现在摘要网格下方。移动端的详情面板紧跟在被选中的摘要卡片之后。展开不生成弹窗；再次点击当前摘要或点击收起按钮时移除详情面板。

摘要卡片本身使用一个覆盖完整可点击区域的按钮，不在按钮内部嵌套其他按钮。展开图标只作为视觉提示。

## 4. 视觉取舍

保留：

- 暖白背景、深棕文字、陶土色点缀；
- 用户提供的机器人头像；
- 头像一层慢速轨道；
- 细边框和编辑式排版。

弱化或删除：

- 删除无内容意义的卡片扫光；
- 弱化标题脉冲与顶部扫光；
- 移除外围节点持续自动漂浮；
- 不增加全页粒子、流体 Shader、光标尾迹、磁吸卡片或 3D 倾斜；
- 不使用突兀的深色或黑色交互面板。

动效采用约 160–420ms 的短过渡，首屏线条可使用较慢但低幅度的循环呼吸。页面同一时间只允许一个主要动态焦点。

## 5. 组件边界与状态流

新增或调整的独立单元：

- `InteractiveProductLoop`：管理 Hero 节点、键盘操作和证据文案。
- `ExperienceEvidenceRail`：接收当前证据类型，渲染轨道与实习高亮。
- `SectionProgress`：通过视口观察更新当前章节。
- `ProjectCaseStudy`：渲染可选择的项目摘要卡片。
- `ProjectDetailPanel`：渲染当前项目的模拟运行与完整结构。

页面级状态只保存：

- 当前主动 Hero 节点；
- 当前展开的实习；
- 当前展开的项目，由 `ProjectsSection` 统一管理；
- 当前可见章节。

Hero 节点到实习证据的映射放在集中式 TypeScript 数据中，组件不通过公司名称字符串猜测关系。

## 6. 可访问性与降级

- Hero 节点使用真实按钮，支持 Enter、Space、可见焦点和 `aria-pressed`。
- 项目卡片触发器提供 `aria-expanded` 与 `aria-controls`。
- 轨道高亮不是唯一的信息表达方式，文字证据始终可见。
- `prefers-reduced-motion: reduce` 下关闭描边、位移、呼吸和滚动揭示，只保留即时状态切换。
- 触屏设备不依赖 hover。
- 动态组件失败时仍显示静态节点、实习内容和项目摘要。

## 7. 性能方案

- 优先使用 CSS transform、opacity、SVG stroke 和原生视口观察。
- 如引入 Motion，只使用 `useScroll`、`useSpring`、`useInView` 等必要能力，不引入整套视觉组件库。
- 指针响应限制在 Hero 图形内部，不注册全页持续指针动画。
- 不使用 Canvas/WebGL Shader，不加载视频背景。

## 8. 验证

自动化验证：

- Hero 三个节点可通过鼠标和键盘切换。
- 每个节点显示正确证据，并高亮正确实习。
- 同一时间最多展开一个实习和一个项目。
- 项目默认不渲染模拟运行详情，展开后渲染，收起后移除。
- `aria-expanded`、`aria-controls` 和 `aria-pressed` 状态正确。

人工验证：

- 1280px 桌面端首屏视觉焦点明确，实习仍是正文第一重点。
- 默认项目区域高度不超过改版前的一半。
- 390px 移动端无横向溢出，按钮点击区域充足。
- 减少动态效果模式下无持续动画。
- 页面不出现黑色面板、强霓虹、粒子背景或明显模板化效果。
